# 拼好字拆字

## 操作步骤

1. **确认范围和现状。** 读取 `scripts/dicts/chaizi_jd6_v2.txt` 中目标字及当前状态；补码目标是 `scripts/dicts/8105.dict.yaml`。41448独有字只在用户明确要求时扩展。
2. **核字形。** 先确认目标字的实际字形、可书写主结构和笔顺。IDS只用于结构线索，不代表笔顺；异体、交叠或罕字用字形/笔顺资料交叉核对。
3. **先分两部，再按笔顺输出。** 合体字固定分两个完整部分：左右取左／右，上下取上／下，三列取左列／其余整体，完整上盖与下部两分。每部最多两码，部内按起首字根或笔画取码，不递归分部；整字为固定根则单取该根。两部可被穿插书写；每个选码对应到实际字形单位的起笔位置，最终按这些单位在整字中的先后交错输出，不提前补写未选笔画。用湘、鸿、营、寒等校准例确定分部；不能确定时记录疑点，不为保旧码另造分法。
4. **核对结果并同步。** 更新总表的拆码、状态和简短依据，同步逐字审核记录；重建索引与词库，运行校验和回归测试。

## 取码决策树

```text
字形、笔顺是否确定？
├─ 否 → 待核，写明疑点
└─ 是 → 整字本身就是固定字根吗？
   ├─ 是 → 直接取一个字根，不补码
   └─ 否 → 能按完整结构分成两个部分吗？
       ├─ 否 → 独体字按真实笔顺取整字前四笔；不足四笔取实际笔数
       │       （如戈→一乛丿丶、丁→一丨、三→一一一）
       └─ 是 → 分别处理两部分（每部最多两键，不递归分部），最后按选码所对应字形单位的起笔顺序交错输出
           ├─ 整部分就是一个现有字根 → 只取该根
           ├─ 起笔是根，后面还能直接认出第二根 → 按序取两根
           │  （如吅→口口，吉→士口）
           ├─ 起笔是根，后面还有未编码部分 → 根＋余部第一笔
           │  （湘：氵／相；相取木，余部目取首笔丨）
           └─ 起笔不是根 → 取该部分前两笔
              （如马→乛乛，辟左部取乛一、右部取丶一）
```

- 始终按实际字形单位的起笔顺序取，不越过先写的非根部分寻找后置字根。完整根的末笔被其他单位插写，不自动否定根；先核笔画归属，根与其他单位不共笔、不截笔、不相互穿透时，按根的起笔位置取码。巫中工与双人、噩中王与四口按此校准，不能只因末横晚写而拆成实笔。
- 两部独立限额，各最多两键；一部是完整根就只取一键，另一部也只能取两键，不借用空位补成四键。班按左王／中间两笔及右王取王、丶丿；斑按王／文王取王、丶一；楙按木／矛木取木、乛丶。彬按林／彡取木木、丿丿。
- 字根限下表；讠、纟等按既有前两笔处理，不临时增加“言、丝”等根。虫是正式字根，映射 i；尸仍不是根，熟悉的部件名不等于现行字根。
- 不把父部件与子部件重复计码，不将难拆块递归展开成全部笔画；田、里不能抽取内部日形。
- 包围外框中断时先判断能否与内件构成两个完整部分；能分则分别限码，并按选码所对应字形单位的实际起笔顺序交错输出，不提前补完外框。不能可靠两分的独体才按整字实际笔顺取前四笔。区、匼、匜、𬸘等已有用户明确裁决的字按其裁值，不用通则覆盖。
- 可按用户裁决取一口；作为另一字的一部分时同样取一口，如河为水一口。
- 耂中土形被撇穿透，不取土；起首取十。十后的余部先横后撇，按根后补余部首笔规则取十一，不漏横而直接跳撇。
- 营、萤及同类草字头盖结构，先把艹冖作为完整上部，再与下部两分；上部取草丶，不省略冖的首点，也不把冖另拆成第三大部。
- 用已确认例字类推：行夹字按彳／其余整体，参照衍、衒、衔；衣夹字参照亵、衮；人盖字参照余；上下复合主体参照寒。湘按氵／相取水木丨，鸿按氵／工鸟取水工丿，优先于旧版江／鸟的分法。字形、分部、根独立性或笔顺经查仍无法确定才待核。

## 唯一字根表

**本表之外的任何部件、偏旁、部首或整字都不算字根。** 不能因为它有名称、像一个字、或能在 IDS 中单独出现，就把它当作字根；只能按本表字根取码，或按规则取真实笔画。

当前唯一认可的25组字根是：

```text
一  贝  草  丶  手  火  金  口  丨  木
女  日  丿  ⺮  虫  犭/豸  人  山  王  工  土/士  水  十  乛  月
```

只用以上25组，不自行增加根。总表规范写作草、手、金、水、人；其中草是艹的码名，不是把整个草字当成艹根；廿／龷顶部的连续一丨丨不独立取草，昔、堇等按实际起笔笔画处理；草字应按艹／早取草日十。实际字形是士/土、犭/豸时可保留对应写法。日的o/e是同一个根的两个形码别名。

| 根 | 键 | 根 | 键 |
|---|---|---|---|
| 一 | a | 贝 | b |
| 草 | c | 丶 | d |
| 手 | f | 火 | h |
| 金 | j | 口 | k |
| 丨 | l | 木 | m |
| 女 | n | 日 | o/e |
| 丿 | p | 虫 | i |
| 犭/豸 | q | 人 | r |
| 土/士 | t | 水 | u |
| 十 | x | 乛 | v |
| 月 | y | 山 | s |
| 王 | w | 工 | g |
| ⺮ | z | — | — |

讠、纟、宀、穴、阝、辶不是独立根；例如讠取丶乛、纟取乛乛。⺮现为独立字根，键位 z；山为 s，王为 w，工为 g。实际竹字头形取⺮，不再按丿一处理；山形和独立王形按新根取码，穿插近似形不机械套用。女、火、犭/豸只在字形确含该部件时取根；豕不是豸。

火根只认实际火形。灬与火形态差异大，按前两笔丶丶处理；不按部件含义合并，也不从烹、煮、热、照等字的四点底取火码h。

## 证据与不确定项

- 记录最终选取单位；同一部分有多个直接可认的现有根时，逐个列出，不只记录首根。保留完整字形结构作依据，但不把父部件和子部件重叠计入。
- 合体字明确记录两个完整部分、每部的一至两码和必要的笔顺证据；不能把三块顺取塞进“独体”或“裁决”规避两部限额。独体、整字根和仍有效的指定特例单列说明。IDS、读音、语义、旧码、码表字母串都不能单独证明拆法。
- 查证后仍不能确定字形、分部、根独立性或笔顺时，拆码留空、状态标`待补`，在依据中说明具体未决点；保留旧候选只作追溯。不能为全覆盖编造形码。

## 文件与验证

- 唯一维护表：`scripts/dicts/chaizi_jd6_v2.txt`，每行四列：`字<TAB>拆码<TAB>状态<TAB>依据`。`沿用`表示未逐字复核，`已核对`须有取码依据，`待补`必须留空。原始`chaizi_jd6.txt`只读。
- 逐字复核依据记在`scripts/dicts/jd6_review.tsv`；它用于追溯，不是第二份码表。两部码连续输出时无需额外标记；交错输出时，在说明开头写`【选码顺序:121】`等标记，1/2依次消费对应部的下一码，并说明实际笔顺依据。完整根按起笔位置定位，不能等写完才输出。索引`jd6_index.md`由生成器创建。
- 改码后执行：
  ```bash
  uv run python scripts/jd6.py
  uv run python scripts/generate.py
  uv run python -m unittest discover -s scripts -p 'test_jd6.py'
  ```
- 确认生成单字和词库与总表一致；实际输入法重新部署和输入测试另行进行。
